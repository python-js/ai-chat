# 方案一：RAG 知识同步（MySQL → pgvector）

> 把 MySQL 中的数据定期同步为向量，复用现有 RAG 检索链路，让 AI 能基于这些数据回答"说明型"问题。

---

## 一、方案概述

将 MySQL 中适合检索的文本数据（产品资料、FAQ、规章制度等）读取出来，经过分块和 embedding 后写入现有的 `DocumentChunk` 表（pgvector）。用户提问时，走已有的相似度检索流程。

**本质**：把 MySQL 当作"另一种格式的文档来源"，后续链路与上传 PDF/Markdown 完全一致。

---

## 二、适用场景

✅ 适合：
- 数据是**说明型文本**（产品介绍、政策条款、常见问题）
- 用户问法是**语义检索型**（"保修政策是什么"、"怎么申请退款"）
- 可以接受**分钟/小时级**的数据延迟

❌ 不适合：
- 需要查询**具体某条记录**（"订单 12345 到哪了"）
- 数据**高频变化**且要求实时准确
- 数据是纯数字/状态码，转成文本后语义丢失

---

## 三、架构设计

```
公司 MySQL（只读）
      │  ① 定时/手动触发同步
      ▼
同步脚本 scripts/sync-mysql.ts
      │  ② SELECT 读取目标表
      │  ③ 拼接成文本 → 分块（800字/100重叠）
      ▼
百炼 text-embedding-v3
      │  ④ 生成向量
      ▼
PostgreSQL DocumentChunk 表（pgvector）
      │  ⑤ 用户提问时相似度检索（现有逻辑）
      ▼
LLM 回答
```

---

## 四、实现步骤（概要）

> 以下为结构设计，具体代码待方案确认后实施。

### 1. 安装依赖
```
npm install mysql2
```

### 2. 新建 MySQL 连接单例 `lib/mysql.ts`
- 参考 `lib/prisma.ts` 的单例模式（防热更新重复建连）
- 使用只读账号，连接池配置保守（connectionLimit: 5）

### 3. 新建同步脚本 `scripts/sync-mysql.ts`
```
① 连接 MySQL，SELECT 目标表（如 product_info）
② 每行数据拼接成一段文本（标题 + 内容）
③ 复用 lib/embedding.ts 的 chunkText 分块
④ 调 embedMany 生成向量
⑤ 写入 DocumentChunk 表（标记 source = 'mysql'）
⑥ 更新同步时间戳
```

### 4. 配置触发方式（二选一）
- **手动**：`npm run sync:mysql`（简单，推荐先用这个）
- **定时**：用 cron / node-cron / 系统计划任务定期执行

### 5. 区分数据来源
在 `DocumentChunk` 表增加 `source` 字段（'upload' / 'mysql'），便于后续按来源清理和重新同步。

## 五、风险与局限（必读）

### 数据时效性
- **同步有延迟**：MySQL 改了数据，要等下次同步才能被 AI 感知。若同步周期是 1 小时，AI 最多会给出 1 小时前的答案。
- **缓解**：缩短同步周期，但会增加 embedding 调用成本。

### 删除不同步（孤儿数据）
- MySQL 里删掉的记录，**不会自动**从向量库删除。AI 可能基于已失效的数据回答。
- **缓解**：每次同步时按 `source='mysql'` 全量清除后重建（简单但费 token），或实现增量 diff（复杂）。

### 结构化数据语义丢失
- 把 `status=2` 这样的字段转成文本后，AI 不一定能正确理解。
- 纯数字、枚举状态码不适合本方案。

### 精确查询不可靠
- 用户问"订单 12345 的状态"，RAG 返回的是"语义相似"的订单，**可能是 12346**。
- 精确查询场景必须用方案二。

### 成本
- 每次全量同步都要重新 embedding 所有数据，数据量大时 token 消耗可观。
- 百炼免费额度有限，需评估数据量。

---

## 六、边界条件

| 场景 | 表现 |
|------|------|
| MySQL 数据量 < 1 万条文本 | 适合，同步快、成本可控 |
| 数据量 > 10 万条 | 全量同步慢，需增量方案 |
| 数据实时性要求 < 1 分钟 | 不适合，改用方案二 |
| MySQL 服务不可用 | 同步失败，但不影响已有向量（旧数据仍可答） |

## 八、与方案二的关系
